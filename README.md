## 🎯 Key Findings & Manuscript Corrections

During the comprehensive audit and reconstruction of the pipeline, several crucial discrepancies were identified and resolved:

### 1. Arithmetic & Partitioning Reconciliation (Reviewer A, Comment 6)
- **7-Class Balanced Corpus:** With 7 classes balanced at 60 clips/signer, the dataset comprises **839 usable clips** (due to 59 usable clips in `kula/Grace`).
- **Data Splitting:** A stratified 70% / 15% / 15% split yields **587 training, 126 validation, and 126 test clips**.
- **Exact Test Set Reproduction:** $126 \text{ test clips} / 7 \text{ classes} = \mathbf{18 \text{ clips per class}}$, which precisely matches the published confusion matrix.
- **Augmentation Order:** Augmenting ($7\times$) applies **only** to the training partition ($587 \times 7 = \mathbf{4,109}$ augmented clips), preventing data leakage.

### 2. Parameter Count Audit (Reviewer B, Comment 10)
- The manuscript (Table 5) reported **177,607 parameters** and asserted "weight sharing" between BiLSTM layers.
- Full layer-by-layer architectural reconstruction in Keras 3 reveals the true parameter count is **604,551 parameters** ($3.4\times$ higher):
  - BiLSTM Layer 1: 396,288 parameters
  - BiLSTM Layer 2: 197,632 parameters
  - Additive Attention: 16,640 parameters
  - Dense & Normalization: ~4,000 parameters
- The revised manuscript updates Table 5 to accurately state 604,551 parameters and removes the invalid weight-sharing claim.

### 3. Empirical Video File Audits
- **Frame Rate:** The video directory contains a mixture of **30 fps and 60 fps** files (rather than uniform 30 fps). Standardizing to $T=60$ frames is evaluated with pad-vs-resample ablations.
- **Sequence Duration:** Clip lengths span **0–176 frames (mean $\approx 26$)**, meaning over half of the 60-frame window is zero padding. Masking layers are structurally vital.
- **Integrity Check:** Two corrupt/0-frame clips (`Britney_000.mp4` instances) are automatically excluded before sampling.

## 🧠 Model Zoo & Experimental Suite

The master notebook (`SwSL_Reviewer_Response_Pipeline.ipynb`) provides standardized evaluation for **12 architectures** across multiple paradigms:

1. **Proposed Architecture:** BiLSTM (128) + BiLSTM (64) + Additive Attention (Bahdanau)
2. **Recurrent Baselines:** Vanilla BiLSTM, Unidirectional LSTM, BiGRU + Attention, Stacked 3-Layer LSTM
3. **Graph Convolutional Networks (GCN):** ST-GCN built on MediaPipe anatomical graph adjacency
4. **Temporal Convolutions:** Dilated Residual Temporal Convolutional Network (TCN)
5. **Raw-Pixel Vision Baselines:** 3D CNN (Conv3D/ResNet3D) & TimeDistributed 2D CNN + LSTM
6. **Transformer:** Multi-head self-attention sequence encoder with sinusoidal positional encodings

### Extensive Ablation Study (23 Variants)
- **Depth & Width:** 1 vs 2 vs 3 layers; units (64-32, 128-64, 256-128)
- **Attention Scoring Functions:** Additive (Bahdanau), Multiplicative (Luong), Dot-product, Scaled Dot-product, Cosine
- **Facial Landmark Inclusion:** Hands+Pose vs. Full 468 Face Mesh vs. Compact 40-Landmark Face Contour
- **Normalization Schemes:** Shoulder-width, Bounding-box, Centroid-centering, Min-max scaling
- **Sequence Standardization:** Post-padding vs. Uniform temporal linear resampling

## 📊 Reviewer Evidence Coverage

All 32 reviewer comments (Reviewer A: A1–A15, Reviewer B: B1–B17) are mapped to executable code cells, figures, and CSV tables:
- **Statistical Rigor (A9):** Holm-Bonferroni corrected McNemar tests, 1,000-sample bootstrap confidence intervals, and 5-fold cross-validation.
- **Signer Independence (B15):** Leave-One-Signer-Out (LOSO) evaluation across signers.
- **Real-Time Benchmarks (B14):** Wall-clock latency distribution (p50, p95, p99) on CPU and GPU with confidence threshold sweep $\tau$.
- **Speech Synthesis (B7):** End-to-end Swahili audio generation using MMS-VITS.

For the complete section-by-section breakdown, see [CHAT_SUMMARY.md](file:///Volumes/MacX/Sw/CHAT_SUMMARY.md) and [README_TRAINING.md](file:///Volumes/MacX/Sw/README_TRAINING.md).

## 🚀 Getting Started

### Option A: Google Colab (Recommended for Training)
1. Upload `SwSL_Reviewer_Response_Pipeline.ipynb` to [Google Colab](https://colab.research.google.com/).
2. Select **Runtime → Change runtime type → GPU (T4 or higher)**.
3. Upload your `raw_videos/` (or `raw_videos.zip`) to your Google Drive root or working environment.
4. Set your execution preset in Section 2:
   ```python
   PRESET = 'quick'     # ~20 min: 1 seed, 40 epochs, smoke-tests every cell
   # PRESET = 'standard' # Publishable run: 3 seeds, 200 epochs, 5-fold CV
   # PRESET = 'full'     # Exhaustive run: 5 seeds, 300 epochs, repeated CV
   ```
5. All results, tables, and models are automatically cached in Google Drive under `SwSL_JCTA_Revision/runs/` to safely support multi-session execution.
